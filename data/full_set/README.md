# `data/full_set/` — пул сцен-кандидатов полномасштабного набора

Собран 08.08.2026 на арендованном сервере (RTX 2080 Ti, 32 ядра, ~1.5 часа).
Сервер погашен, всё скачано и проверено. **Пересобирать не нужно.**

## Что это и зачем

Это **пул кандидатов**, а не готовый набор. Из него предстоит отобрать
120–180 сцен под квоты `task.md` — так же, как в пилоте отбирали 20 из 117.
План фазы и разбор требований — [`../../docs/FULL_SET_PLAN.md`](../../docs/FULL_SET_PLAN.md).

| | Сцен | Задач | Кадров | Объектов |
| --- | --- | --- | --- | --- |
| LIBERO (`spatial`/`object`/`goal`/`10`) | 800 | 40 | 1600 | 4880 |
| SimplerEnv (bridge) | 96 | 4 | 96 | 432 |
| **Итого** | **896** | **44** | **1696** | **5312** |

## Файлы

| Файл | Что это |
| --- | --- |
| `task_inventory.jsonl` | **объединённый инвентарь, 896 сцен — работайте с ним** |
| `libero_inventory.jsonl`, `simpler_inventory.jsonl` | сырые выгрузки сборщиков, источник для объединения |
| `visibility_review.html` | дашборд разметки видимости, готов к открытию в браузере |
| `images/libero/`, `images/simpler/` | 1696 кадров, битых путей нет |
| `collection_provenance.json` | **чем и с какими параметрами собрано** — пины репозиториев, версии, правило сэмплирования, счётчики |

BDDL-файлы лежат отдельно, в [`../libero_bddl/`](../libero_bddl/) — все 40 задач
LIBERO, включая `libero_10`. Инвентарь хранит только **путь** внутрь репозитория
LIBERO, поэтому без этой копии определения сцен были бы потеряны вместе с
сервером.

**У SimplerEnv BDDL нет и не требуется** — это понятие LIBERO/robosuite. Сцена
bridge воспроизводится по `source.gym_env_name` + `source.episode_id` +
`source.reset_seed` + пину коммита SimplerEnv, и всё это есть в записи.

## Как собрано

- **LIBERO:** 20 init state на задачу, равномерно разнесённых по доступным 50
  (`round(i*49/19)`), а не подряд — ради разнообразия раскладок.
- **SimplerEnv:** все 24 эпизода каждой из четырёх bridge-задач.
- **Усадка 40 шагов** нулевого действия перед съёмкой во всех 896 сценах
  (`source.settle_steps`). Без неё предметы попадают в кадр в полёте — так был
  собран пилотный инвентарь, и часть сцен там отсеивалась именно поэтому.
  **Сравнивая с пилотом, всегда сверяйте это поле.**

Размер выбран под квоты, а не на глаз. Связывающая квота — пространственная:
пространственный язык есть лишь в 12 задачах LIBERO из 40, и 20 init state дают
ровно **×4** запаса к цели в 150 отобранных сцен. Остальные квоты ×11–×21.
Доля bridge (96 из 896 ≈ 11%) держит пропорцию `task.md` «8–12 задач из 60–80».

## Как запускать инструменты по этому набору

**Все скрипты конвейера по умолчанию смотрят на замороженный пилот**, а не
сюда. Это не оплошность, а следствие того, что пилот был единственным набором,
когда их писали. Флаги обязательны:

```bash
# дашборд видимости (уже сгенерирован, пересоздать при изменении инвентаря)
python3 scripts/generate_visibility_review.py \
  --input  data/full_set/task_inventory.jsonl \
  --output data/full_set/visibility_review.html

# применить выгруженные из дашборда правки
python3 scripts/apply_visibility_review.py <corrections.json> \
  --inventory data/full_set/task_inventory.jsonl
```

`apply_visibility_review.py` **откажется** писать в пилотный инвентарь без
явного `--allow-pilot` — защита поставлена 08.08.2026 именно потому, что
дефолт ведёт на замороженные данные.

Остальные скрипты (`generate_selected_scenes.py`,
`sync_selected_tasks_visibility.py`, `build_frames_v0.py`, `export_prompts.py`,
`validate_frames.py`) такой защиты пока не имеют — **проверяйте пути перед
запуском**. У `sync_selected_tasks_visibility.py` пути вообще захардкожены,
без аргументов.
