# Валидация стенда: GreenVLA на полном bridge-наборе

Вопрос этого прогона один: **воспроизводит ли наш пайплайн число, которое авторы
GreenVLA публикуют о своих чекпойнтах.** Не «какой SR у модели по-русски» — только
английская каноническая строка задачи, ровно та, что зашита в сцену SimplerEnv.

## Почему пилотных четырёх сцен было мало

Две независимые причины, и вторая важнее.

Первая — мощность. Четыре эпизода дают интервал Уилсона шириной под 65 п.п.:
он накрывает почти любое заявленное число, поэтому «совпало» из него читать
нельзя.

Вторая — состав задач. **Все четыре SimplerEnv-сцены пилота — это одна задача,
`widowx_stack_cube`**, самая тяжёлая из четырёх bridge-задач. Заявленные авторами
72.9% (R1) и 80.5% (R2) — среднее по всем bridge-задачам, включая заметно более
лёгкие (`put_eggplant_in_basket`). То есть мы сравнивали не просто мало эпизодов,
а другой набор задач.

## Что запущено

`data/full_set/simpler_inventory.jsonl` → `scripts/export_prompts_simpler_en.py`
→ 22 сцены, четыре задачи (`widowx_stack_cube`, `widowx_carrot_on_plate`,
`widowx_spoon_on_towel`, `widowx_put_eggplant_in_basket`), только
`en_canonical`. Три модели GreenVLA, 66 эпизодов.

```bash
python scripts/export_prompts_simpler_en.py
SLAVA_RUN_POOL=harness_validation_greenvla \
conda run -n slava-notebook python scripts/run_rollouts.py \
  --models greenvla_r0 greenvla_r1_bridge greenvla_r2_bridge \
  --variants en_canonical --prompts data/full_set/prompts_simpler_en.jsonl \
  --num-shards 2 --shard-index 0    # второй шард — index 1, вторая GPU
python scripts/harness_validation.py --pool harness_validation_greenvla --by-task
```

Успех берётся из самого симулятора (`info["success"]` у ManiSkill), а не из
нашей авторазметки, — поэтому число прямо сопоставимо с авторским и не зависит
от вопроса о точности `auto_label.py`.

Собрано 07.08.2026 на арендованном инстансе с 2×RTX 3090 (Ampere, то есть
собственный `dtype` чекпойнта, без обходных путей для Volta).

## Результат

```
модель                     наше en_canonical    95% CI      заявлено   вывод
GreenVLA-R0                  0/22 =  0.0%    [ 0.0;14.9]     33.3%    НЕ совпадает
GreenVLA-R1 (bridge)         5/22 = 22.7%    [10.1;43.4]     72.9%    НЕ совпадает
GreenVLA-R2 (bridge, RL)     5/22 = 22.7%    [10.1;43.4]     80.5%    НЕ совпадает
```

По задачам:

```
                     stack_cube  carrot_on_plate  spoon_on_towel  eggplant_in_basket
GreenVLA-R0             0/8            0/8             0/3              0/3
GreenVLA-R1             1/8            1/8             1/3              2/3
GreenVLA-R2             2/8            3/8             0/3              0/3
```

Три вывода, и они не сводятся один к другому.

**Стенд SimplerEnv рабочий.** R1 берёт 2 из 3 эпизодов `eggplant`, R2 — 3 из 8
`carrot_on_plate`: захват, перенос и укладка проходят целиком. Пайплайн,
сломанный так, как можно было бы подумать по числам пилота, этого не дал бы.

**Пилотный набор сцен был конфаундом.** Все четыре SimplerEnv-сцены пилота —
`widowx_stack_cube`, и по этой задаче все три модели действительно почти на
нуле (0/8, 1/8, 2/8). Заявленные авторами средние берутся по четырём задачам,
включая лёгкие. Сравнивать 1/4 по одной задаче с 72.9% по четырём было нельзя.

**Но и на честном наборе воспроизведения нет.** У R1 и R2 около 23% против
73% и 80%; интервалы заявленных чисел не накрывают. Разрыв стал измеренным на
22 эпизодах и четырёх задачах, а не следствием выборки сцен.

R2 при этом сильнее R1 ровно там, где пилот его и мерил (`stack_cube` 2/8
против 1/8, `carrot_on_plate` 3/8 против 1/8), но проигрывает на `eggplant`
(0/3 против 2/3). Итоговые 5/22 у обоих — совпадение агрегатов при разных
профилях по задачам, а не одинаковое поведение.

**Ноль у R0 — отдельная аномалия.** 0/22, на всех четырёх задачах, на тех же
сценах и тем же кодом, которым R1 и R2 набирают успехи. Это свойство именно
этого чекпойнта (или нашей его конфигурации), а не среды. Гипотезы — в
`.claude/skills/slava-greenvla`.

## Как это читать

Сравнение внутри модели (между вариантами инструкции, то есть Δlang) идёт
внутри одного сеанса сбора и настройками точности не затронуто. Абсолютный SR
двух моделей, собранных на разном железе, без оговорки сравнивать нельзя — что
чем собрано, записано в `data/collection_runs.json`.
