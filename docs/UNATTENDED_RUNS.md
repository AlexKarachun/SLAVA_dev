# Долгие и автономные сессии: как запускать

Справочник по вопросу «оставляю машину на сутки-двое, работай сама». Здесь —
где запускать, что мешает работе продолжаться, и что проверить перед уходом.
Правила расхода бюджета — в skill `slava-budget-pacing`, состояние на диске —
`slava-long-sessions` и [`WORKLOG.md`](WORKLOG.md).

Проверено на этой машине 07.08.2026.

## Коротко

| Где запускать | Лимиты видны | Переживёт обрыв терминала | Переживёт закрытие крышки |
| --- | --- | --- | --- |
| VS Code-расширение | ✗ | ✗ | ✗ |
| Терминал без tmux | ✓ | ✗ | ✗ |
| Терминал + tmux (локально) | ✓ | ✓ | только с запретом сна |
| Терминал + tmux на сервере | ✓ | ✓ | ✓ (машина не спит) |

Для автономной смены — **терминал под tmux**. Локально плюс запрет сна, либо на
сервере.

## Почему не VS Code-расширение

Проценты 5-часового и недельного лимита приходят только в payload статуслайна,
а статуслайн — фича терминального UI: в расширении он не запускается никогда, и
кэш `~/.claude/usage-cache.json` остаётся пустым. Чинить нечего, это не поломка
настройки. Без процентов агент не знает, сколько осталось до стены, и вынужден
работать «как при небольшом остатке», то есть заметно осторожнее, чем мог бы.

Расход и размер контекста при этом видны везде — из транскрипта сессии:

```bash
python3 scripts/budget_log.py                       # потрачено, контекст сейчас
python3 scripts/budget_log.py --mark "что сделали"   # строка в docs/BUDGET_LOG.md
```

## tmux: от чего он спасает, а от чего нет

tmux держит сессию на стороне машины, где запущен. Обрыв ssh, закрытое окно
терминала, упавший терминальный эмулятор — работа продолжается, потом
`tmux attach`. Чего он **не** умеет: пережить сон или выключение самой машины.

```bash
tmux new -s slava        # запустить
# Ctrl+b d               — отсоединиться
tmux attach -t slava     # вернуться
tmux ls                  # что вообще живо
```

## Локально: ноутбук с закрытой крышкой

Закрытие крышки MacBook усыпляет систему целиком — вместе с tmux и Wi-Fi.
`caffeinate` тут не помогает: он не перекрывает засыпание по крышке.

```bash
sudo pmset -a disablesleep 1     # разрешить работу с закрытой крышкой
sudo pmset -a disablesleep 0     # ВЕРНУТЬ ПОСЛЕ СМЕНЫ
```

Вариант без закрытой крышки — оставить открытой и запретить сон только на
адаптере: `sudo pmset -c sleep 0`.

Обязательно: **питание от сети** (на батарее всё кончится за несколько часов) и
проверка, что Wi-Fi не отваливается. Настройки этой машины на 07.08.2026:
`displaysleep 0` на адаптере (экран не гаснет), но `sleep 1` — то есть система
уснёт даже с открытой крышкой, если не поменять.

Проверка перед уходом: закрыть крышку на пять минут, открыть, посмотреть, шли
ли ходы за это время.

## На сервере

Repo приезжает `git clone`, дальше `tmux new -s slava` и запуск. Один раз нужно
залогиниться в Claude Code — лимиты тратятся из того же аккаунта.

Что там работать **не** будет: ручная валидация роллаутов и генерация клипов —
кадры (16 ГБ) есть только на ноутбуке, офсайт-копии мы не держим (см.
`rollouts/RUNS.md`). GPU-задачи, очевидно, требуют GPU.

## Чтобы работа не кончилась сама

Главная ошибка: сессия переживёт обрыв связи, но после выполнения задачи просто
встанет на приглашении ввода — спросить-то некого. Автономный режим должен сам
себя продлевать: `/loop` без интервала, где агент планирует следующее
пробуждение (`ScheduleWakeup`) после каждой единицы работы, в том числе пережидая
сброс лимита.

**Разрешения — вторая по частоте причина остановки.** Любой вызов инструмента,
упирающийся в запрос подтверждения, вешает смену до вашего возвращения. Перед
уходом нужные разрешения прописываются в `.claude/settings.json`, либо
выбирается режим, который не спрашивает. Обсуждать это стоит отдельно и
осознанно: полномочия выдаются заранее и целиком.

## Чек-лист перед уходом

1. Терминал + tmux, не расширение.
2. Питание от сети; сон запрещён (локально) или машина серверная.
3. Разрешения выданы — ни один шаг не упрётся в подтверждение.
4. Режим самопродления запущен (`/loop`), задача сформулирована так, чтобы её
   хватило на всю смену.
5. `docs/WORKLOG.md` заполнен: что делаем, следующие действия, границы.
6. Рабочее дерево чистое, всё закоммичено и запушено.
7. Полномочия на коммит и пуш в автономном режиме подтверждены (`AGENTS.md`).
8. Проверено, что данные для запланированной работы лежат на той машине, где
   идёт смена.

## Когда вернулись

```bash
tmux attach -t slava
git log --oneline -20          # что сделано
cat docs/WORKLOG.md            # где остановились
cat docs/BUDGET_LOG.md         # во что обошлось
sudo pmset -a disablesleep 0   # если включали
```
